Swertres daily engine

Run npm run swertres from the repository. It fetches the primary draw-date table from https://www.lottopcso.com/swertres-results-today-history-and-summary/ with a 30-second timeout and 2 MB bound. There is no stale-file fallback. Archive dates come from visible labels, not hyperlinks. Leading zeros and repeated digits remain strings. Latest Oct 9–11 2026 rows were manually cross-checked against https://www.pcso.gov.ph/searchlottoresult.aspx on Oct 12; official direct HTTP fetch can return 403, so this check was performed through the readable official page. This is not a claim that every historic row has official verification.

The engine acquires a session advisory lock before backing up the entire ledger schema using a READ ONLY REPEATABLE READ transaction. It durably writes a unique JSON file with 0600 permissions to /home/kit/ledger-backups before beginning the write transaction. Fetch failures, parsing failures, source combination conflicts, overlapping engines and incomplete existing picks fail safely. Existing combinations and actual pick rows are immutable. Same-result re-fetch updates fetched_at; scores use insert-on-conflict-do-nothing. No existing application data is deleted or updated.

Results are retained; the active learning and frequency window is four inclusive calendar months, currently June 12 through October 12. Every elapsed missing draw is explicitly listed in coverage. Dates with future scheduled draws are not called missing yet. Missing rows are never invented.

Learning uses four transparent heuristics, hot overall digit frequency and hot position frequency from the last 30 calendar days capped at 90 completed winning draws, current overdue/cold digit frequency, and unordered pairs from the last 30 completed draws. These recent windows also apply inside historical walk-forward predictions. Each scores all 1,000 combinations, then deterministic date-seeded diversity selects four unique combinations. A daily walk-forward backtest begins only after 30 draws. Historical predictions see only dates strictly before their evaluation date. Actual afternoon picks can use completed same-day results, but historical predictions cannot. Weights update by normalized bounded multiplicative reward for straight matches, exact multiset any-order matches and a small partial-digit term. Trials count individual hypothetical pick/draw evaluations, not winning days. All strategy stats and weight logs are labeled historical walk-forward backtest, never actual saved picks. Rolling backfills rebuild backtest stats/logs deterministically while never replacing actual picks.

Actual picks have one date and apply only to that date's remaining draws. eligible_after is the next strictly future scheduled time; an after-9pm invocation uses next-day and records no eligible same-day draws. Scoring additionally requires the scheduled draw timestamp to be strictly after pick creation. This prevents crediting completed draws. Rambolito is an exact repeated-digit multiset equality. digit_hits counts multiset intersection; position_hits counts exact position equality. Predictions are rankings, not probabilities, and learning does not establish improved lottery odds.

GET /api/swertres is protected by the same session guard as the rest of Ledger. It returns four current picks, up to 120 actual historical pick rows with scores, latest 30 results, labeled strategy stats, ten digit frequencies, elapsed missing-draw coverage and fetched updatedAt. Responses use a consistent read-only database snapshot.

Run npm run test:swertres for parser, repeated-digit scoring, weights, leakage, eligibility, deterministic selection and coverage checks. The API also returns analysis with ranked recent hot digits, ranked hot positions, recent pairs, double/triple draw counts, yesterday’s real saved-pick performance and a plain-language summary. Yesterday with no saved picks is explicitly marked no picks recorded, with null hit totals, not a fabricated test. Every successful run appends a daily analysis to swertres_daily_runs even when current picks already exist. Today’s original v1 picks remain immutable; newly generated future-date picks use recent-window v2. Migration 007 adds the analysis log. Migration 006 is additive and follows the existing RLS and anon/authenticated revocation convention. Take a full backup before invoking npm run migrate as well.

Per-draw update

The draw argument is required. Use node scripts/swertres-daily.js --draw 2pm, node scripts/swertres-daily.js --draw 5pm, or node scripts/swertres-daily.js --draw 9pm. npm run swertres -- --draw 5pm is equivalent. Scheduled generation is intended for 11am before 2pm, 3pm before 5pm, and 6pm before 9pm Manila time. The caller owns these schedules.

Each target has four unique picks keyed by pick_date, draw_time and slot. Run after the target time is rejected before writes. A target that occurs while processing also aborts before insertion. All known completed earlier draws, including today, inform target picks. Historical walk-forward backtests remain prior-date-only. Scoring requires the same pick date and exact draw time, with result timestamp strictly after creation. No group is ever replaced on rerun.

Migration 008 safely creates swertres_draw_picks and swertres_draw_scores separately. It preserves the legacy daily-pick tables and rows verbatim, with no copy masquerading as new predictions. The API returns current per-draw groups and per-draw history. Daily analysis evaluates all genuinely saved per-draw groups for yesterday.

Each pick exposes true_odds with straightPct, anyOrderPct and permutations. Straight is 0.1 percent. Exact any-order odds are 0.6 percent for three distinct digits, 0.3 percent for a double and 0.1 percent for a triple. model_score_pct is that candidate's weighted ensemble score divided by the total score across all 1,000 combinations, times 100. This is relative model strength, not a calibrated win probability. Both are in the API and JSON command output.

Persisted odds contract

Migration 009 adds odds JSON and model_score percentage to each saved per-draw pick. odds has straightPercent, anyOrderPercent and permutations. model_score is normalized across all 1,000 combinations before selecting four, and model_score_label explicitly says Model relative score, not win chance. Any-order odds describe exact permutations only, with no prize-specific assumption. Existing true_odds and model_score_pct aliases remain for the initial UI integration. Migration backfills only these new metrics from immutable stored combos and original ensemble breakdowns, never regenerating picks or changing their creation timestamp.

Confirmed picks

The user-confirmed original October 12 four are 074, 182, 144 and 946. Migration 010 adds confirmed draw-pick and score tables, preserving both earlier tables untouched. Active generation and API read these confirmed tables. The confirmed original four retain their actual original creation time, are scoped only to 17:00, and store odds plus current recent-window model-score annotations. New 9pm picks use their own group and do not reuse the 5pm rows. top_pick is computed from the saved numeric score per date/time group, sorted highest first; it is not inferred from slot. Scores are sum-normalized across all 1,000 candidates, not min-max confidence.
